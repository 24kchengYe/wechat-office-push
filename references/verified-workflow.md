# 已验证工作流与边界

本文件记录把操作经验提升为技能规则的证据锚点。它不保存论文正文、公众号登录态、个人路径或后台 token。

## 已验证主路径

### TUS 论文双账号路由（2026-08）

- 同一份核验后的论文事实源可分别渲染 BCL 与 TUS 草稿。
- BCL 论文草稿选择“论文推荐”合集；TUS 自有公众号不选择合集。
- 两个账号的固定页尾、二维码和模板不能混用。
- 草稿状态必须按账号分别记录，不能用一个账号的状态覆盖另一个账号。

### BCL 普通组内论文（2026-08-09）

- 从 PDF 生成正常论文推荐，并用 BCL 已发表普通论文模板创建副本。
- 已验证标题、作者、期刊、正文 DOI、后台原文链接、4 张论文图和推荐语可独立替换。
- 历史模板中的专题/单元推广区可安全删除，同时保留 BCL 通用页尾。
- 保存为草稿后重新打开核验；未执行发布。

### BCL 重要论文长版（2026-08）

- 结构化 Word 稿可按 Heading 1 / Heading 2 / Caption 识别摘要、方法、结果与讨论、研究意义及 5 张图。
- 历史文章只提供版式骨架；作者、引文、年份、推荐语和正文必须全部来自当前输入，不能保留示例论文常量。

## 已知失败与形成的规则

1. 微信编辑器滚动或重新渲染后，UI Automation 控件引用会失效。提交原文链接后必须重新获取根节点，再验证新 DOI。
2. 高 DPI 和多显示器会放大坐标偏移。优先操作可访问性控件及其当前矩形，不把一次会话的物理坐标写入技能。
3. 点击“原文链接”的父级容器可能误触相邻“原创”设置。应点击当前 URL 文本本身，并在确认后校验 URL。
4. 历史模板会携带旧作者、DOI、责任编辑或项目推广块。保存前必须验证新内容存在且旧内容不存在。
5. 公众号“保存为草稿”按钮重新出现不等于保存失败；完成定义是保存后重新打开并核验标题、正文和后台设置。

## 适用边界

- PDF 抽取与三格式渲染可跨平台；微信后台自动化当前只验证过 Windows。
- 微信后台 UI、历史模板结构或合集交互变化后，应先更新 fixture/test，再恢复自动填充。
- 二维码、Logo、历史模板及文章片段属于账号资产；本仓库保持 Private，公开再分发需另行确认授权。
